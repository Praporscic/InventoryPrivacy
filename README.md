# Inventory & Stock Manager website

GitHub Pages (Jekyll) site for the Inventory & Stock Manager iOS app, served at
https://praporscic.github.io/InventoryPrivacy/.

- `/` — privacy policy (this URL is registered in App Store Connect, so keep it serving the policy)
- `/about/` — landing page: features, screenshots, App Store button
- `/articles/` — article index; each article lives in `_articles/`

The site is available in 15 languages. English is served from the root (the URLs above); every other
language lives under its own prefix: `/zh/`, `/ja/`, `/es/`, `/fr/`, `/de/`, `/ko/`, `/pt/` (Portuguese, Brazil),
`/it/`, `/ru/`, `/ro/`, `/ar/` (right-to-left), `/tr/`, `/nl/` and `/id/` — for example `/de/about/` or `/de/articles/`.
A globe button in the header switches language and keeps you on the equivalent page.

## How translations work

- `_data/languages.yml` lists the languages (URL prefix, `<html lang>`, text direction).
- `_data/i18n/<code>.yml` holds all page text for one language: the UI strings (header, footer, buttons), the
  privacy policy, the About page, and the article-index and 404 text. `en.yml` is the master; every other file
  must have exactly the same keys. Fields holding HTML (`intro`, section `body`, `free_sub`, `free_links`) are
  output as-is, so write `&amp;` there; all other fields are plain text and escaped by the templates.
  Keep the placeholders `[n]`, `[privacy_url]` and `[overview_url]` unchanged.
- The pages themselves are thin stubs (for example `de/about/index.html`) that pick a layout
  (`_layouts/privacy.html`, `about.html`, `articles.html`) and a `lang`; the layouts render the text from the data files.
- Each article exists once per language as `_articles/<code>/<slug>.md` (English stays in `_articles/<slug>.md`).
- `hreflang` links, the language switcher and `llms.txt` are generated from `_data/languages.yml`.

## Adding an article

Create `_articles/<slug>.md` with this front matter (the slug becomes the URL `/articles/<slug>/`):

```yaml
---
title: "Article title"
description: "One or two sentences (about 150 characters) used in search results and social cards."
date: YYYY-MM-DD 09:00:00 +0000   # required for sorting; not shown on the page
reading_time: 4
ref: <slug>     # same value in every language version; links the translations together
faq:            # optional, adds a visible FAQ and FAQPage structured data
  - q: "Question?"
    a: "Answer."
---
```

Write the body in Markdown starting at `##` headings (the layout renders the `h1`). The article list,
sitemap and `llms.txt` update automatically.

To translate it, add `_articles/<code>/<slug>.md` for each language with the same `ref`, plus

```yaml
lang: <code>
permalink: /<code>/articles/<slug>/
```

and link to `{{ '/<code>/' | relative_url }}` / `{{ '/<code>/about/' | relative_url }}` instead of the English pages.
Until a translation exists, the language switcher on that article sends visitors to the article index of the
chosen language, and no `hreflang` is emitted for the missing version.

## Adding a language

1. Add an entry to `_data/languages.yml`.
2. Copy `_data/i18n/en.yml` to `_data/i18n/<code>.yml` and translate it.
3. Create the three stub pages `<code>/index.html` (`layout: privacy`), `<code>/about/index.html`
   (`layout: about`, `schema: app`) and `<code>/articles/index.html` (`layout: articles`), each with
   `lang: <code>` and `page_key: privacy|about|articles` (copy them from an existing language folder).
4. Translate each article into `_articles/<code>/`.

## Notes

- The App Store link (`app_store_url` in `_config.yml`) has no country code, so Apple sends each visitor to their own storefront.
- `sitemap.xml` is generated by `jekyll-sitemap`; `robots.txt` and `llms.txt` are templates in the repo root.
- Shared markup lives in `_layouts/` and `_includes/`; styles are in `assets/css/style.css`; the language-menu
  behaviour is in `assets/js/site.js`.
- The 404 page contains every language and shows the one matching the URL prefix or the browser language.
